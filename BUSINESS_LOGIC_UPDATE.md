# Обновление бизнес-логики и интерфейсов

Дата: 3 августа 2026 года.

## Клиентский сайт

- На мобильных устройствах добавлено раскрывающееся меню с пунктами «Войти», «Создать аккаунт», «Баланс», «Личный кабинет» и «Выйти» в зависимости от состояния авторизации.
- В личном кабинете на телефоне используется выезжающее боковое меню с затемнением страницы, текущим разделом, всеми страницами кабинета и кнопкой выхода.
- Меню закрывается после перехода, по нажатию на фон и клавише Escape. При открытом меню прокрутка страницы блокируется.
- Авторизация восстанавливается из сохранённых access/refresh token после обновления и повторного открытия сайта.
- На странице пополнения можно выбрать один из нескольких доступных кошельков.
- На странице вывода указаны только понятные клиенту правила: заявки принимаются каждую среду по времени Алматы, обработка занимает от 1 часа до 3 дней.
- Форма вывода отключена в остальные дни. Ограничение действует и в интерфейсе, и на сервере.
- Дата ближайшей среды форматируется в часовом поясе `Asia/Almaty`, а не в часовом поясе браузера.
- Убраны тексты о backend, worker, endpoint, Binance API, внутренних операциях и других деталях реализации.
- На странице вознаграждений оставлены фактически полученные вознаграждения и премиальные реферальные бонусы. Неясная кнопка будущих графиков удалена.
- Добавлен раздел «Пригласить друзей» с персональной ссылкой, кодом, статистикой и историей приглашённых.
- Регистрация по ссылке `?ref=КОД` автоматически заполняет реферальный код.
- Публикации подняты сразу под главный экран и поставлены первым пунктом публичного меню.
- На странице компании указано, что компания работает с 2023 года, стремится помочь людям получать дополнительный заработок, а участие в программах обеспечивается автомобилями компании.

## Программы

Вместо старых категорий `game/application` введены три понятных уровня:

```text
starter  → Старт
standard → Стандарт
premium  → Премиум
```

Из таблицы программ удалены колонки `slug` и `category`. Публичная страница программы открывается по UUID. У программы остаются только необходимые бизнес-поля: название, уровень, описания, фотография, стоимость, срок доступа, параметры вознаграждений и активность.

Демонстрационные программы:

- «Старт Драйв»;
- «Драйв Плюс»;
- «Премиум Драйв».

## Универсальные адреса пополнения

Добавлена таблица `deposit_wallets`. Администратор может:

- добавить несколько адресов разных сетей для пополнения в USDT;
- задать название каждого кошелька;
- изменить порядок отображения;
- включить или отключить адрес для новых заявок;
- изменить реквизиты;
- включить автоматическую проверку только для поддерживаемой конфигурации;
- скопировать адрес из таблицы.

Клиент выбирает адрес до создания заявки. Выбранный адрес сохраняется в заявке, поэтому последующее отключение кошелька не меняет уже выданные реквизиты.

Первая автоматическая интеграция работает для:

```text
Сеть:      Ethereum Mainnet
Актив:     USDT
Стандарт:  ERC-20
Провайдер: Infura
```

Для другой сети адрес можно сохранить и показывать клиентам, но автоматическую
проверку необходимо отключить до подключения соответствующего провайдера.

## Реферальная система

Каждому пользователю создаётся уникальный `referral_code`. При регистрации по реферальному коду сохраняется связь с пригласившим пользователем.

Правила начислений:

1. После успешной активации любой программы приглашённым пользователем пригласивший получает 10% от стоимости этой программы.
2. Если приглашённый активировал премиальную программу, за каждое фактическое вознаграждение приглашённого пригласивший дополнительно получает 2 USDT.
3. Оба типа начислений выполняются в одной серверной транзакции с уникальными ключами идемпотентности, поэтому повторная обработка не дублирует бонус.

Новые типы операций:

```text
referral_purchase_bonus
referral_reward_bonus
```

## Вывод по средам

Backend рассчитывает доступность вывода по `Asia/Almaty`. При попытке создать заявку не в среду возвращается ошибка `withdrawal_day_closed`. Это предотвращает обход ограничения прямым запросом к API.

Настройки:

```env
BUSINESS_TIMEZONE=Asia/Almaty
WITHDRAWAL_ALLOWED_WEEKDAY=2
WITHDRAWAL_PROCESSING_MIN_HOURS=1
WITHDRAWAL_PROCESSING_MAX_DAYS=3
```

## Публикации

Администратору больше не нужно вводить технический `slug` публикации. Адрес создаётся автоматически из заголовка с уникальным суффиксом. Существующие адреса публикаций сохраняются при редактировании.

## Миграция базы данных

Миграции:

```text
backend/alembic/versions/0003_business_logic.py
backend/alembic/versions/0004_infura_erc20.py
```

Они:

- создаёт таблицу адресов пополнения;
- добавляет реферальные поля пользователей;
- заполняет реферальные коды существующим пользователям;
- переносит уровни программ;
- сохраняет уровень в снимке уже активированной программы;
- удаляет `subscription_plans.slug` и `subscription_plans.category`;
- связывает заявку на пополнение с выбранным кошельком;
- переименовывает тип операции `subscription_purchase` в `program_purchase`.
- добавляет параметры сети, провайдера, контракта токена и подтверждений;
- переводит старую таблицу входящих переводов в универсальную
  `blockchain_deposits`;
- добавляет курсор сканирования Ethereum-блоков;
- подключает проверку событий `Transfer` USDT ERC-20 через Infura;
- сохраняет старые адреса других сетей, но отключает их для новых заявок.

Перед применением в production необходимо сделать резервную копию PostgreSQL.

## Основные новые endpoints

```text
GET   /api/v1/wallet/deposit-addresses
GET   /api/v1/referrals/me
GET   /api/v1/admin/deposit-wallets
POST  /api/v1/admin/deposit-wallets
GET   /api/v1/admin/deposit-wallets/{wallet_id}
PATCH /api/v1/admin/deposit-wallets/{wallet_id}
```

Программы теперь читаются по UUID:

```text
GET /api/v1/plans/{plan_id}
```
