# Лотереи: билеты, розыгрыш и выдача призов

Лотерея оплачивается с внутреннего USDT-баланса. Каждый купленный билет получает отдельный уникальный код. Продажа доступна только в опубликованный период, а выбор победителей — не раньше даты результатов `draw_at`.

## Состояния лотереи

- `draft` — черновик, клиентам не показывается;
- `published` — опубликована, билеты продаются в заданный период;
- `awaiting_confirmation` — победители выбраны и ожидают решения администратора;
- `completed` — все доступные призовые места подтверждены;
- `cancelled` — зарезервировано для сценария отмены.

## Создание в админ-панели

1. Откройте **Лотереи → Создать лотерею**.
2. Укажите название, описание и URL обложки.
3. Задайте цену билета, начало продаж, дедлайн и дату результатов.
4. Укажите общий лимит билетов и лимит на пользователя.
5. Добавьте полный текст правил и изменяйте `rules_version` при каждом изменении условий.
6. Добавьте один или несколько призов.
7. Нажмите **Опубликовать**.

После первой покупки нельзя изменять цену, даты, лимиты, правила и состав призов. Название, описание, обложку и контакт менеджера можно исправить без изменения финансовых условий.

## Призы

### Денежный приз

Тип: `balance`.

После подтверждения победителя сумма идемпотентно зачисляется на доступный USDT-баланс через `WalletService`. Создаётся операция `lottery_prize_credit`, уведомление в личном кабинете и email.

### Неденежный приз

Тип: `physical`.

Для приза или всей лотереи обязательно укажите Telegram менеджера. После подтверждения победитель получает уведомление и письмо с контактом для получения приза.

## Покупка билета

Пользователь:

1. открывает лотерею;
2. выбирает количество билетов;
3. принимает актуальные правила лотереи;
4. оплачивает билеты с внутреннего баланса.

Покупка защищена `Idempotency-Key`, лимитами и блокировкой строки лотереи. В покупке сохраняются версия правил, IP и User-Agent.

## Выбор победителей

После наступления `draw_at` администратор выбирает один из вариантов.

### Случайный розыгрыш

Кнопка **Провести случайный розыгрыш** использует `secrets.SystemRandom`. Один билет не может занять два призовых места. Один пользователь может выиграть несколько раз, если у него несколько разных билетов и это допускают опубликованные правила.

### Ручной выбор

Администратор выбирает приз и билет. Билет можно найти по коду или email пользователя. Неподтверждённый выбор можно отменить и заменить другим билетом.

Ручной и случайный выбор записываются в журнал аудита отдельно.

## Подтверждение

До подтверждения результат является внутренним предварительным выбором и не показывается пользователю как победа. После подтверждения:

- денежный приз поступает на баланс;
- неденежный приз создаёт поздравление с контактом менеджера;
- победитель появляется в публичных результатах с частично скрытым email;
- отправляется email;
- действие записывается в аудит.

Можно подтвердить одного победителя или всех ожидающих победителей.

## Проверка базы

```bash
docker compose exec db sh -lc 'psql \
  -U "$POSTGRES_USER" \
  -d "$POSTGRES_DB" \
  -c "
SELECT l.title, l.status, l.sales_end_at, l.draw_at,
       count(DISTINCT t.id) AS tickets,
       count(DISTINCT w.id) AS selected_winners
FROM lotteries l
LEFT JOIN lottery_tickets t ON t.lottery_id = l.id
LEFT JOIN lottery_winners w ON w.lottery_id = l.id
GROUP BY l.id
ORDER BY l.created_at DESC;
"'
```

## Юридическое замечание

Платные розыгрыши, правила определения победителей, возраст участников, налогообложение призов, возвраты и необходимость лицензии регулируются по-разному в разных странах. Перед публичным запуском текст правил и саму механику нужно проверить у юриста для каждой страны работы. Тексты в проекте являются техническим шаблоном, а не заключением о законности конкретной модели.
