# Запуск Automotive Club Mobile

В этой поставке добавлен отдельный нативный проект `automotive_mobile/`. Исходные файлы клиентского сайта и админки сохранены без изменений. Бэкенд работает с прежней общей базой; предусмотрено совместимое обновление защиты повторных финансовых запросов.

## 1. Обновить существующий сервер

Следуйте `MOBILE_BACKEND_CHANGES.md`: примените миграцию `0008_mobile_deposit_idempotency`, перезапустите API. Проверьте `/api/v1/system/config`: `financial_request_idempotency_supported` должен быть `true`. Сайт и мобильное приложение указывают на этот же сервер. Никакая рабочая база или сервер не были изменены во время подготовки архива.

## 2. Запустить мобильный проект

Нужен Node.js от 22.13. Из папки `automotive_mobile`:

```bash
npm ci
cp .env.example .env
# Указать адрес того же API и сайта в .env.
npx expo start --clear
```

В PowerShell вместо `cp` можно выполнить `Copy-Item .env.example .env`. Подробности запуска Android и iPhone находятся в `automotive_mobile/README.md`. Для эмулятора Android локальный API использует `10.0.2.2`; для телефона — LAN-адрес компьютера; для рабочего сервера нужен HTTPS.

## 3. Получить установочный файл

Команды Android APK/AAB и iOS Ad Hoc/TestFlight находятся в `automotive_mobile/docs/BUILD.md`. Нужны ваша учётная запись Expo и собственные данные подписи. Для iOS нужен Apple Developer, либо Xcode на Mac для локального запуска. Сгенерированные папки `android/` и `ios/` не включены в ZIP: Expo заново создаёт их из `app.config.ts` и зависимостей, команды предусмотрены инструкцией.

APK/IPA в этой поставке отсутствуют. Выполнены TypeScript, 78 мобильных тестов, 120 тестов реального FastAPI на отдельной SQLite, миграционные проверки, Hermes-экспорт Android/iOS и генерация нативных проектов. Установка на реальные устройства, SMTP и настоящие blockchain-переводы не проверены.

## Документы

- `automotive_mobile/docs/API_MAP.md` — соответствие экранов настоящим API.
- `automotive_mobile/docs/SOURCE_AUDIT.md` — перенесённые сценарии и расхождения с описанием.
- `automotive_mobile/docs/TESTING.md` — точный отчёт проверок и сценарии приёмки.
- `automotive_mobile/docs/PUSH.md` — текущие уведомления и требуемые серверные изменения для push.

Комиссия текущей настройки: 10% сверх суммы получателю (100 + 10 = 110 USDT), окончательные значения определяет сервер. Завершённые выводы показывают сохранённые исторические данные. Push при закрытом приложении требует отдельной серверной реализации; внутри приложения работают существующие уведомления и переписка с непрочитанными счётчиками.
